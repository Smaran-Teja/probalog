4 Symbolic sets🔗

 (require probalog/hash-set) package: probalog

The natural representation of a Datalog database whose facts exist only in some worlds is a set whose membership is symbolic. Rosette provides no such structure, so Probalog supplies one: a symbolic set maps each element to its guard: the condition under which the element is a member. Elements are concrete; only membership is uncertain. All bindings of this module are re-exported by probalog/core.

> (define x (guard-var 1/2))
> (set-add (set 1 2) 3 x)

(sym-set

  1

  2

  [#<cpointer> 3])

Elements present in every world print bare; the rest print as [guard element] pairs. Here 3 is present in half the worlds. The set operations lift to guards: a union disjoins the guards of a shared element, an intersection conjoins them.

> (define y (guard-var 1/2))
> (guard-equiv? (set-member? (set-union (set-add (set) 1 x)
                                        (set-add (set) 1 y))
                             1)
                (guard-or x y))

#t

> (guard-equiv? (set-member? (set-intersect (set-add (set) 1 x)
                                            (set-add (set) 1 y))
                             1)
                (guard-and x y))

#t

procedure

(sym-set? v) → boolean?

  v : any/c
Predicate for symbolic sets. A symbolic set is also a sequence of two values, the element and its guard.

syntax

(set elem ...)

Constructs a symbolic set containing each elem in every world. Elements are concrete; to add one under a condition, pass a guard to set-add.

(subset? st1 st2) → any/c

  st1 : sym-set?
  st2 : sym-set?
The usual set operations, lifted to symbolic sets. Results are guards rather than Booleans: set-member? returns the element’s guard, and set-empty? and subset? the condition under which they hold. The optional guard argument to set-add adds v only in the worlds where that guard holds; it is passed explicitly rather than written as (when guard (set-add st v)) because a guard is not a Racket Boolean and so cannot be branched on.

procedure

(set-equal? st1 st2 [keys]) → boolean?

  st1 : sym-set?
  st2 : sym-set?
  keys : (or/c list? #f) = #f
Whether the two sets are semantically equal: every element’s guard in st1 is logically equivalent to its guard in st2. Because guards are canonical this is decided by comparison rather than by a solver. When keys is a list, only those elements are compared — which is what makes fixpoint detection affordable, since elements untouched by the latest round are guaranteed to be unchanged.

syntax

(for/sym-set (for-clause ...) body ...+)

syntax

(for*/sym-set (for-clause ...) body ...+)

Iteration forms that accumulate a symbolic set. Each iteration’s body may return either an element, which is added in every world, or an element and a guard as two values.

Both accumulate into a transient mutable hash and convert to a symbolic set only at the end. When the same element is produced by many iterations — as when one rule derives the same conclusion along many paths — this merges the duplicates in place, so the cost of building the element’s guard is paid once per distinct element rather than once per iteration. The mutable hash never escapes, so the forms are observationally pure.
