2 Engine🔗

 (require probalog/core) package: probalog

The engine is also usable directly from roulette/example/disrupt, without going through the surface syntax. A program is a list of base facts paired with probabilities and a list of rules.

> (define db
    (run-datalog
     (list (cons (fact 'Edge (list "a" "b")) 0.5)
           (cons (fact 'Edge (list "b" "c")) 0.6))
     (list (rule (fact 'Path (list 'x 'y))
                 (list (fact 'Edge (list 'x 'y))))
           (rule (fact 'Path (list 'x 'z))
                 (list (fact 'Path (list 'x 'y))
                       (fact 'Edge (list 'y 'z)))))))
> (query-fact db (fact 'Path (list "a" "c")))

(pmf [#t 0.3] [#f 0.7])

> (observe-fact db (fact 'Path (list "a" "c")))
> (query-fact db (fact 'Edge (list "a" "b")))

(pmf [#t 1])

2.1 Saturation🔗

procedure

(run-datalog base-fact-probs rules) → sym-set?

  base-fact-probs : (listof (cons/c fact? (real-in 0 1)))
  rules : (listof rule?)
Saturates the database, returning the symbolic set of all derivable facts. Each base fact is admitted under an independent guard variable of the given probability, and the immediate-consequence operator is iterated to a fixpoint. Equivalent to (saturate-semi (make-base-set base-fact-probs) rules).

procedure

(saturate-semi base rules) → sym-set?

  base : sym-set?
  rules : (listof rule?)
Iterates the immediate-consequence operator over base until no fact’s guard changes. Takes the database rather than building it, so a caller that wants control over the variable order can construct it with make-base-set itself.

2.2 Facts, rules, and queries🔗

struct

(struct fact (name args))

  name : symbol?
  args : list?
A predicate applied to arguments. An argument that is a symbol is a variable; any other argument is a constant. Facts appearing in a base-fact list or in a query must be ground.

struct

(struct rule (head body))

  head : fact?
  body : (listof fact?)
A Horn clause: head is derivable for any binding of its variables under which every clause of body holds.

procedure

(query-fact result f [#:where where]) → pmf?

  result : sym-set?
  f : fact?
  where : (or/c string? #f) = #f
Returns the probability distribution of f’s membership in result, conditioned on all observations made so far — that is, P(f ∧ evidence) / P(evidence).

This is what query computes for (set-member? result f), but it is computed directly: a guard is a diagram Rosette cannot see into, so the engine does its own conditioning rather than going through Roulette’s query and observe!. Where query would return #f because no possible world remains, this raises an error instead.

Every one of these procedures takes an optional where, a source location like "reachability.rkt:5:0" used to attribute a failure to the statement responsible. The language supplies it; code calling the engine directly has no reason to.

procedure

(query-result->string p) → string?

  p : pmf?
How the language displays a query result: a distribution with a single possible outcome renders as that outcome, and anything else as the distribution. query-fact itself always returns a pmf?; this only affects what a ? statement prints.

So a printed #t or #f means the answer is provably certain, not that its probability rounded to 1 or 0. An outcome is dropped only when it is impossible, which query-fact decides with guard-known-false? rather than by weighing — see there for why the two differ.

procedure

(observe-fact result f [#:where where]) → void?

  result : sym-set?
  f : fact?
  where : (or/c string? #f) = #f
Conditions the current distribution on f being derivable, so that all subsequent queries report posteriors.

Observing something of probability zero would divide by zero and leave every later query reporting nothing, so it is rejected instead: f must be derivable in at least one world that satisfies the observations already made.

procedure

(observe-not-fact result f [#:where where]) → void?

  result : sym-set?
  f : fact?
  where : (or/c string? #f) = #f
Like observe-fact, but conditions on f not being derivable, and rejects the observation when f is certain.

procedure

(observe-guard g [#:where where]) → void?

  g : any/c
  where : (or/c string? #f) = #f
Conditions on an arbitrary formula, such as a disjunction of several facts’ membership tests, subject to the same check.

procedure

(make-base-set base-fact-probs) → sym-set?

  base-fact-probs : (listof (cons/c fact? (real-in 0 1)))
Builds the initial database: each fact guarded by an independent variable of its probability. It is the only place a base fact’s guard is created, which makes it the one place that decides what order the variables come in. Called by run-datalog.
